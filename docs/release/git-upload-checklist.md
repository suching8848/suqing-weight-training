# Git 上传核对清单

源码项目：当前仓库根目录。

本次仅准备材料。后续上传对话应先核实本目录是否已有Git仓库、远端地址和未提交变更，不自行猜测远端名称，不直接运行旧发布或回滚脚本。

## 可供审核的内容

- 当前运行源目录 `SuQingWeightTraining/`：物品、配方、穿戴、训练、沙盒、翻译及新增美术资源。
- 项目说明 `README.md`、`README.en.md`、版本记录 `CHANGELOG.md`。
- 开发和验证工具 `tools/`、`tests/`。
- 本目录的中英文Workshop BBCode介绍和版本说明。
- 美术原图、提示词及最终导出说明，以主交付记录的实际路径为准。

## 上传前

1. 读取实际 `git status` 与远端配置；没有仓库时，先按上传对话中用户授权确定仓库归属和可见性。
2. 审查差异，确认公开文档没有个人存档倍率、Steam个人信息、备份目录、日志全文或凭据。
3. 保留 `.gitignore` 对 `.validation/`、`build/`、Python缓存的排除；不要把测试缓存、个人存档、本机审计快照和本地备份作为源码上传。
4. `legacy/v0.1.0-java/` 是旧实现档案，不能混入运行包；若拟提交历史档案，先明确其用途并检查是否有不应公开的内容。
5. 检查新增图片是否属于项目本次生成的素材，封面不写游戏版本号。项目未明确指定许可证时，不擅自添加开源许可证。
6. 运行当前验证和打包工具，复读运行包版本及清单；Lua测试通过不等于图标已在游戏内验收。
7. 显式暂存所需文件并复读暂存差异。提交、推送、创建远端及发布按后续对话的实际授权执行。

## 上传后

记录实际仓库URL、分支、提交SHA、对应发布包清单哈希和Steam Workshop物品ID。源码已推送、Workshop已上传、本机已部署是三个独立状态，应分别记录。
